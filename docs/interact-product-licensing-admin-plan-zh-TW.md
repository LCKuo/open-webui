## 一句話架構

Website + Interact AI 共同構成平台：Website 管理公司、平台方案、延伸產品授權與共用錢包；Interact AI 負責 AI API Key、模型權限、推論及 AI 用量彙整，再交由 Website 帳務結算。**Web SaaS**（例如 CRM）以公司／產品實例授權，產品自行建立任意數量的本機使用者；**App 型延伸產品**以公司授權加同時使用人數上限管理。這兩類是 CRM／其他延伸產品的授權分類，Interact AI 作為平台內部功能，不另建立一份獨立產品訂閱或 App 使用租約。能登入、產品可用、功能可用與錢包能付款仍須分別判斷。

```text
Interact 平台（Website + Interact AI）
  ├─ Website：主要入口、公司帳號、平台方案、延伸產品授權、錢包與帳本
  │    ├─ AI 用量結算：接收 Interact AI 回報
  │    └─ 非 AI 扣款 API：直接服務 Website／CRM／其他 App
  └─ Interact AI：平台 AI 功能、API Key、模型權限、推論與用量彙整
       ↑ CRM／其他 App 的 AI 功能使用 Interact AI 產出的 API Key

延伸產品由 Website 授權中心管理
  ├─ CRM／Web 辦公軟體：公司／實例授權，本機使用者不限數
  └─ 手機／桌面 App：公司授權、同時使用上限、短效使用租約
```

使用者主要在 Website 查看方案、儲值、餘額與所有產品用量。AI 與非 AI 費用共用經授權的企業錢包及帳務服務，依來源分類查帳；規劃不為 Interact AI 另建可獨立儲值的錢包。

## 1. 授權層次

| 層次 | 主站回答的問題 | 建議資料 |
| --- | --- | --- |
| 身分 | 誰買產品、誰在 App 使用？ | Website 公司／App 使用者用穩定 ID；Web SaaS 可有自己的本機帳號，不強制一一對映 Website 成員 |
| 公司產品授權 | 這家公司買了哪個產品、何時到期？ | 產品、授權狀態、起訖、寬限、方案／合約來源 |
| 授權策略 | 產品是否限制人數？ | `instance_unlimited_users` 或 `concurrent_users`；前者無人數欄位，後者設定同時使用上限 |
| 同時使用 | App 現在有多少不同使用者正在操作？ | 按公司／產品／使用者的短效租約原子計數；不是已建立帳號數，也不是瀏覽器分頁數 |
| 功能與配額 | 哪些模組、功能與額度可用？ | 版本化 entitlement：功能代碼、數量上限、政策版本 |
| 計費 | 付費動作能否執行、扣了多少？ | 工具代碼、費率版本、預扣、實扣、帳本與用量事件 |

個人購買可先視為「只有一位成員的公司／工作區」，避免同一產品同時維護個人版與企業版兩套授權邏輯。不要把「登入成功」直接等同「所有產品都可使用」，也不要把錢包不足等同 SaaS 授權到期。

### 產品、模組與方案的邊界

- **產品**是獨立系統，例如 CRM、文件辦公、庫存、某個桌面 App；給穩定 `product_key`，不可拿顯示名稱當識別碼。
- **平台 AI 功能**由 Interact AI 提供，隸屬 Website 的平台方案與功能配額；不為它另建一個延伸產品、第二份公司訂閱或 App 同時使用限制。既有 AI 子帳號、模型及工具配額須按現況保留，未經遷移驗收不改成另一種計數方式。
- **模組／功能**是產品內可授權的能力，例如 CRM 的 BD、AM 或某項報表；不要每個按鈕都建立一個新產品。
- **方案**是可銷售的授權組合和上限，採版本化快照。調價不改寫既有合約。
- **加購**只增加 App 的同時使用上限、功能或額度；Web SaaS 不出現人數加購欄位。不要再生一套獨立的授權判斷。
- **非 AI 計量**依產品的可稽核事件扣款；不冒充 AI token。AI 模型用量由 Interact AI API Key 的既有結算路徑處理。

### 同一平台的兩種計費入口

| 付費動作 | 呼叫入口 | 主站台如何入帳 |
| --- | --- | --- |
| CRM／其他 App 呼叫 AI | 使用 Interact AI 產出的 API Key 呼叫 AI API；現有 CRM Agent Token 過渡方式見第 6 節 | Interact AI 向 Website 預扣及結算實際 AI 用量 |
| Website／CRM／其他 App 的非 AI 功能，例如文件轉檔、資料處理或報表產出 | 由受信任後端直接使用 Website 扣款 API；不需先呼叫 AI | Website 驗證付費權限、按核定工具費率預扣與結算 |

兩種入口都回到 Website 的同一套帳務權威。AI API Key 用於 AI 存取；直接扣款須使用 Website 核發、限公司與產品範圍的授權，不能拿 AI Key 當任意扣款憑證。共用錢包必須讓兩條路徑的預留與扣款互相可見，避免同時使用時超扣。帳本需區分 AI／非 AI、產品、工具、操作者與操作 ID；同一次 AI 推論只結算一次，若另收 App 服務費，須有獨立、事先告知的收費項目。

### Company User 與授權中心的責任邊界

`Company User` 不縮成只有「加 Token」，也不應繼續作為產品授權的第二個編輯入口。它保留**公司帳號與基本資料、主站成員身分、錢包餘額、Token 儲值、付款與用量紀錄**；並可顯示「已開通產品」唯讀摘要與連到授權中心的管理入口。CRM 類 Web SaaS 的本機使用者仍在產品內管理，不搬進 `Company User`。

**授權中心是唯一可編輯的平台方案與延伸產品授權來源**：分別管理「平台方案與 AI 功能」及「CRM／其他產品授權」，負責開通／暫停、有效期限、功能、產品實例綁定，以及 App 的同時使用上限。AI API Key 的建立與撤銷由平台內的 Interact AI 功能管理；不再要求公司另購一份 Interact AI 產品授權。Company User、產品畫面與計費預扣都讀取同一份授權結果，不各存一份可互相覆蓋的設定。

## 2. Admin 介面怎麼長

### 平台管理員（Interact 內部）

Admin 的全站側邊欄新增頂層 **授權中心**，不要只在 `Company User` 詳情頁塞一個小面板。授權中心內提供 **平台方案與 AI 功能、公司產品授權、產品與方案、變更紀錄**；既有 **客戶公司／Company User** 繼續放帳號、公司及帳務資料。平台 AI 設定與延伸產品授權在同一管理入口呈現，AI 不列成第二個獨立購買產品。最常用的兩條入口指向**同一個授權編輯頁**：

```text
Admin 側邊欄 → 授權中心 → 選公司 → 產品與授權
客戶公司／Company User → 選一家公司 → 已開通產品摘要 → 到授權中心管理
```

公司頁先顯示一張緊湊表格，不預設展開所有產品：

| 產品 | 授權策略 | 狀態 | 方案／版本 | 到期日 | 使用人數 | 功能摘要 | 操作 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| CRM | Web SaaS | 使用中 | 商務版 v2 | 2027-09-30 | 不限，由 CRM 自管 | AM、BD | 管理 |
| 文件辦公 | Web SaaS | 試用 | 試用版 v1 | 2026-10-21 | 不限，由產品自管 | 文件、簽核 | 管理 |
| 桌面工具 | App 同時使用 | 使用中 | 標準版 v1 | 2027-09-30 | 目前 2／上限 5 | 核心工具 | 管理 |

上表僅列延伸產品。公司的平台方案、AI 功能、模型及工具配額另在同頁的「平台方案與 AI 功能」區管理；沿用現行限制的實際意義，不顯示未實作的 AI 同時上線人數。

點「管理」才開詳情：共通頁籤為 **授權、功能與額度、用量帳本、變更紀錄**。Web SaaS 額外顯示產品實例與管理員入口，不列出或限制產品本機使用者；App 額外顯示**目前在線、同時使用上限、最近釋放紀錄**。新增授權是「選產品 → 選方案／起訖 → 若為 App 再設同時使用上限 → 預覽 → 確認」。變更必須顯示何時生效、會影響誰；強制釋放異常租約或暫停授權須記錄原因。此處可連到 Company User 的儲值與帳單，但不在授權中心再做一套錢包編輯。

### 客戶公司管理員（自助）

在主站企業入口提供 **我的產品** 唯讀授權摘要，並可查看自身平台方案與 AI 功能。客戶管理員可看已購授權、產品實例、App 目前使用量；公司資料、主站成員、用量、餘額及儲值仍走 Company User 的既有帳務入口。Website 是主要管理入口，集中顯示 AI 與非 AI 用量及來源，並提供 AI 功能／API Key 管理的導向。Web SaaS 使用者仍在各產品內建立與管理，不需要回主站配置席位。客戶管理員不能改費率、延長到期日、調高同時使用上限或替其他公司開通產品。App 達上限時顯示「目前同時使用人數已滿」，不是籠統的 403。

既有 **企業 Profile → 系統整合** 保留，不另開一個客戶端授權編輯頁。它只顯示已連接產品的實例、連線狀態、允許的連線 scope、最近使用及解除／重新綁定；CRM 綁定與 Agent 工作流範圍沿用目前流程。此處的 Agent scope 是連線權限，**不是**公司產品授權。解除連線不取消訂閱、不刪產品資料；產品到期也不應悄悄刪除連線紀錄。未來 App 的 OAuth 授權紀錄可列在此處，但 App 登入本身不需要額外手動「綁定企業」。AI API Key 仍在 Interact AI 管理，這裡最多顯示狀態與跳轉，不展示密鑰。

### 產品使用者

從主站「我的產品」或產品自己的網址進入。產品仍維持熟悉的日常操作；跨產品授權錯誤用一致訊息呈現：**同時使用已滿（只限 App）、授權已到期、功能未包含、餘額不足、帳號停用**各有明確處理入口，不籠統寫「權限不足」。

## 3. 管理操作規則

1. **建立客戶**：主站建立購買產品的公司。App 使用者以主站成員身分登入；Web SaaS 可在產品內自行新增任意本機使用者，不靠 Email 網域自動授權。
2. **開通產品**：平台 admin 建立公司授權，設定試用／付費、起訖與方案版本；只有 `concurrent_users` 產品需填同時使用人數上限。
3. **管理使用者**：Web SaaS 的新增／停用使用者與工作角色留在產品內。App 可管理哪些主站成員有資格使用，但資格名單人數不限；實際限制是同一時間的不同活躍使用者數。
4. **到期／欠費**：到期日及寬限期由主站決定；到期預設阻止新增／付費操作，但保留指定期間的唯讀和資料匯出，避免「停用＝資料消失」。欠費、授權過期、餘額不足分開處理。
5. **暫停／恢復**：平台 admin 可暫停公司產品授權；恢復後原設定保留。全程留下前後值、原因、時間和操作者。
6. **改方案**：先預覽功能或 App 同時使用上限縮減是否影響現有使用者，指定立即或下期生效；資料和歷史不可因降級而刪除。
7. **桌面／手機 App**：一次計數一位不同使用者，不按裝置／分頁重複計數。用短效租約與心跳維持占用，正常離開立即釋放、斷線則逾期釋放；租約取得須由主站原子操作防止超賣。只有真的需要限制安裝數時才另加裝置啟用。

## 4. 共用資料模型與 API 契約

建議最小資料實體：`products`（含 `license_policy`）、`product_clients`、`plan_versions`、`company_product_grants`（App 含 `max_concurrent_users`）、`product_instances`（Web SaaS）、`grant_feature_snapshots`、`concurrent_user_leases`、`company_memberships`、`pricing_versions`、`wallets`、`usage_reservations`、`usage_events`、`ledger_entries`、`license_audit_events`。`company_product_grants` 是延伸產品授權的唯一權威資料；平台方案與 AI 功能先沿用既有公司設定，再由同一授權中心集中管理，不新增一筆獨立 Interact AI 產品授權。Company User 只讀授權摘要，保留原有公司與帳務資料。App 租約以公司／產品／使用者唯一，取得上限時必須原子計數；所有授權變更保留版本與歷史。錢包、預扣與帳本須沿用並擴充既有帳務服務，不能因增加非 AI 扣款而另建互不相通的餘額。

### App 讀取，先保持簡單

- **App 身分登入**：Website 提供標準授權碼 + PKCE 與可驗證 token；每個 App 註冊自己的 client、callback 與 scopes。App 不收集 Website 密碼。[OAuth 安全最佳實務](https://www.rfc-editor.org/rfc/rfc9700.html)建議這類授權流程的安全措施。Web SaaS 的本機使用者可沿用既有登入。
- **我的產品**：對 App 使用者回傳公司產品授權、角色、到期及同時使用上限；Web SaaS 只需公司／產品實例授權，不必把全部本機使用者同步成主站成員。
- **授權檢查**：Web SaaS 由已綁定產品實例帶 `company_id`、`product_key`、`feature_key` 查授權；App 則用主站核發的使用者 `sub` 與公司查授權並取得／續租同時使用名額。兩者都回 `reason_code`、`entitlement_version`、`checked_at`。
- **同時使用租約**：App 每位使用者原子取得一份短效租約、活動時續租、退出時釋放；多裝置同一使用者只占一份。瀏覽器關閉或網路斷線靠到期回收，不把登入 token 的 10 天有效期當作在線時間。
- **非 AI 付費執行**：產品後端可直接向 Website 預扣，再執行、結算或取消，無須經過 Interact AI；要求 `operation_id` 冪等、回查、帳本及對帳。AI 呼叫則由 Interact AI 沿用平台內部結算。詳見 [Website 直連整合規格](./interact-website-app-integration-target-zh-TW.md)。
- **變更通知**：主站發產品授權、同時使用上限、停用、費率版本事件；產品驗簽後清快取。未收到通知時仍須短 TTL 重查，付費操作即時核對。

這些是**擬議能力，不是現有 API**。權限計算應集中在主站同一服務函式，admin 畫面、`我的產品`、App 授權檢查與計費預扣共用同一結果，避免 UI 顯示「可用」但扣款時拒絕，或反過來。若主站暫時無法查詢，新的付費操作應失敗關閉；一般唯讀操作可依產品政策使用短效快取。

### 平台 AI Key 與延伸產品

CRM 與其他延伸產品使用平台 AI 時，目標是採用 **Interact AI 產出的 API Key**，由 Key 所屬的已驗證使用者對應企業帳務；產品可按使用者／用途管理可獨立輪替及撤銷的 Key。AI 存取資格來自平台方案、Key scope 及模型權限，不增加一份獨立 Interact AI 產品訂閱，也不因 AI 呼叫額外占用一份 App 人數名額。沒有 AI 的付費功能直接使用 Website 扣款 API。

現行 AI Key 只有固定模型讀取與聊天 scope，尚無強制產品綁定；「把產品名寫在 Key 名稱」只能協助辨識，不是安全隔離。可逐步補上主站穩定使用者／公司 ID 與 Key 用途的對映，供歸屬與稽核使用；不能因此要求每位 CRM 本機使用者重建主站帳號。CRM 現有 Agent Token 是相容性例外，是否遷移及如何支援既有 Agent scope 須另行實作驗收，不能宣稱目前已全部改成 API Key。

## 5. 授權與計費的邊界案例

| 狀況 | 預期行為 |
| --- | --- |
| CRM 公司有授權，產品內新增第 100 位使用者 | 可由 CRM 管理員新增；主站不以人數攔截 |
| App 公司已達同時使用上限，但仍可建立新使用者 | 可建立帳號；新使用者須等其他人離開或提高上限才能開始使用 |
| 同一 App 使用者開兩個裝置／分頁 | 仍計為一位同時使用者，不重複占用 |
| 功能不在方案內 | 可進產品，但鎖住該功能並說明方案差異 |
| 授權有效、錢包不足 | 可檢視既有資料；需扣款的操作不啟動 |
| App 使用者被移出公司 | 撤銷該公司的 App 授權和租約；歷史資料不刪除 |
| 公司有兩個產品 | 各自授權與功能；只有同時使用策略的產品才有限額，共用企業錢包並在同一帳本按產品分類 |
| AI Key 被撤銷 | 僅 AI 功能不能用；非 AI 功能照 Website 授權與計費運作 |
| App 完全不使用 AI，仍有付費功能 | 可直接使用 Website 的受限扣款 API，不要求先建立 AI Key |
| AI 與非 AI 工作同時消耗同一錢包 | 共用預留與扣款的原子檢查，不能各自讀取舊餘額後超扣 |
| 同時重試同筆付費操作 | 同一 `operation_id` 回同一結果，不重複扣款 |
| 授權到期後續約 | 保留原成員與資料，按新授權版本恢復可用功能 |

## 6. 不讓既有 CRM 使用者重新學習

CRM 現有登入、任意數量本機使用者、`owner/manager/sales/viewer` 與 AM／BD 工作角色全部保留。主站只判斷「這家公司／CRM 實例是否有有效產品授權」，**不設定人數上限、不逐一核對 CRM 本機使用者、不要求 CRM 用戶重建 Website 帳號**。細部商機、報價、AM／BD 權限仍由 CRM 判斷。先做產品實例的**只記錄不攔截** shadow check，確認既有客戶沒有被誤鎖後再啟用公司級攔截。現有 `crm` 專用企業綁定可作過渡，不應直接複製 N 份到新產品。

現有 CRM 仍使用企業綁定及短效 Agent Token。此次架構修正不撤銷既有綁定、不輪替憑證、不移除 Agent scope，也不直接修改 `service@chengsyin.com` 的平台方案。日後讓 CRM AI 存取採 API Key 時，必須先確認所需 Agent 能力、企業歸屬與計費都能銜接，再遷移；產品本機使用者仍由 CRM 管理。

## 7. 建議分期

1. **基礎**：確立產品 ID、授權策略、公司／App 使用者穩定 ID、方案版本和 audit；在 Admin 側邊欄建立授權中心及「公司 → 產品與授權」。Web SaaS 不出現席位欄位，App 顯示同時使用上限。Company User 只顯示授權摘要與跳轉，仍保留帳務操作。
2. **登入與查詢**：App 接 Website 使用者登入、entitlement 與同時使用租約；Web SaaS 接公司／產品實例授權，CRM 先 shadow check。
3. **非 AI 計費**：產品工具／費率、餘額、預扣結算取消、冪等與對帳，先讓目前不使用 LLM 的 App 有完整可驗收扣款。
4. **客戶自助與遷移**：盤點 Company User 和其他舊頁面的產品授權欄位，先將既有資料映射到授權中心並雙邊比對；再把舊編輯入口設唯讀／導向同一頁，最後移除舊寫入路徑。不得讓兩個頁面各自儲存不同授權。公司 admin 可查看產品期限與 App 同時使用量；CRM 漸進切換公司級授權，保留無限本機帳號與既有業務資料。
5. **平台 AI 串接與相容性**：改善 Website／Interact AI 內部穩定身分對映、用量來源及 Key 生命週期，驗證 CRM／其他 App 的 AI 用量只結算一次；另行驗收 CRM 舊 Agent Token 的遷移相容性。Interact AI 不新增獨立產品訂閱或 App 活躍使用者租約。桌面裝置啟用按延伸產品需求增加。

**先不要做**一套涵蓋所有產品內細部權限的萬用 RBAC 編輯器、永久離線授權碼、每個產品各自的會員／錢包資料表，或把所有功能開關塞到一張公司設定表。這些會讓 admin 難以理解，也會讓授權結果無法追溯。
